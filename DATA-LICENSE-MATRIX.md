# XFINLAB Intelligence API v1 — Data License Matrix

**Purpose:** before scaling XFINLAB's Intelligence API into the primary commercial product ("API-first" pivot), this maps every *paid* `/intelligence/v1/*` endpoint to the upstream data source(s) it actually depends on, and that source's real license status.

**Source of truth:** this file does not introduce new judgments about licensing — it rolls up what already exists in `services/license_registry.py` and `services/source_registry.py` (both already in this repo, last updated 2026-08-10) and maps it onto the *specific endpoints being sold*, which neither of those files does directly. If a source's status changes, update `license_registry.py` first; this file should be regenerated from it, not edited independently.

**2026-08-11 update (RESOLVED):** `ALPACA_API_KEY_ID` / `ALPACA_API_SECRET_KEY` were absent from production, confirmed live via Railway logs showing every price/OHLC-touching endpoint 100% yfinance-backed. AJ has since signed up for Alpaca and set both keys in Railway's Variables tab. Verification along the way surfaced a second, unrelated bug: this app never called `logging.basicConfig()` anywhere, so every `logger.info()` call across the whole codebase (not just this diagnostic) was silently swallowed by Python's default WARNING-only last-resort handler — uvicorn's own access-log lines were unaffected (uvicorn configures its own loggers independently), which made the app look like it was logging normally while it wasn't. Fixed in `backend/main.py` (commit `50b0d67`). With that fixed, production logs now confirm: **`Alpaca served OHLC for AAPL (6mo, 1d)`** — Alpaca is live and serving US-symbol requests as of 2026-08-11. Every row below marked "confirmed live (Alpaca never fires)" is now stale and superseded — see the per-endpoint table for the corrected status.

## What this confirms

Every endpoint that touches raw price/OHLC data (`technical`, `stress-test`, `regime-signal`, and the price-context leg of `debate` and `intel/*`) now actually uses Alpaca (confirmed live via production logs, 2026-08-11) for US-listed symbols. That risk is resolved for US symbols.

A second, previously-conservatively-flagged risk turned out to be real and is now the biggest open item: **investing.com's RSS content**, used across `events`, `sentiment`, `intel/latest`, `intel/{ticker}`, and `world/market-map`. A direct fetch of investing.com's own webmaster-tools/RSS page (2026-08-11) found Fusion Media's site-wide footer notice: *"It is prohibited to use, store, reproduce, display, modify, transmit or distribute the data contained in this website without the explicit prior written permission of Fusion Media and/or the data provider."* That is an explicit, unambiguous restriction, not an ambiguous ToS to interpret — see `services/license_registry.py`'s `investing_com_rss` entry, upgraded from `unknown/medium` to `non_commercial/high`.

`market_data_service.py` (the fully-yfinance, unmitigated `/api/market` and `/api/analyze` consumer endpoints) is confirmed **not** used by any Intelligence API v1 endpoint — its risk is real but belongs to the consumer surface that this pivot is de-emphasizing anyway, not the product being sold.

2. **Decide the non-US-symbol gap** (Alpaca is US-exchange-only; HK/TW/etc. tickers always use yfinance). Researched 2026-08-11, two different answers per market:
   - **Taiwan**: genuinely promising. TWSE (Taiwan Stock Exchange) publishes an official OpenAPI (`openapi.twse.com.tw`) including per-security daily OHLC data (`個股日成交資訊`), released under Taiwan's government-wide **Open Government Data License v1.0** — verified by direct fetch of `data.gov.tw/license`: perpetual, worldwide, non-exclusive, irrevocable, royalty-free license to reproduce/distribute/adapt for any purpose including commercial derivative products, only real obligation is an attribution notice. This is a similar risk profile to `sec_edgar` (already rated low risk in this registry). `services/source_registry.py` already has a `twse_official` entry, but it's currently wired only into `trending_stocks_service.py`'s daily top-20 leaderboard endpoint (`MI_INDEX20`), not into the OHLC chain `technical_analysis_service.py` actually needs — extending it to cover individual-ticker historical bars would be new engineering work (not just a licensing decision), but the licensing groundwork is now confirmed clean if that work gets prioritized.
   - **Hong Kong**: no equivalent found. HKEX's own official historical data (`hkex.com.hk/eng/ods`) is a paid subscription product, not a free API — confirmed by direct fetch, the site is literally a subscribe-and-pay portal. No free official alternative surfaced in this pass. Realistic options are: pay for an HKEX data license, find and vet a commercial-tier third-party provider, or make an explicit scope decision that HK-listed tickers are yfinance-backed (documented, not hidden) until/unless that changes.
   - Given this split, a reasonable interim scope statement: *"XFINLAB Intelligence API v1 guarantees commercially-licensed data sourcing for US-listed symbols today; Taiwan-listed symbol support is a near-term roadmap item; Hong Kong and other non-US markets currently use a best-effort fallback source pending a licensing decision."* That's honest and specific rather than a blanket disclaimer.
